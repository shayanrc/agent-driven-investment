## Why this is unblocked now

Two recent merges removed the blockers that prevented bug #129 from being
fixed in-situ:

- **V1.4 date-aligned splits (merged `2ba6576`).** Anchors the test window to
  a fixed universe-calendar date instead of "last 1500 rows per ticker", so
  H=100 / H=150 / H=200 specs no longer have their test segment eaten by the
  horizon mask. Plan: `docs/gbdt/V1.4_date_aligned_splits_plan.md`.
- **`--snapshot-end` pin (merged `4341a62`).** Makes the universe-cache key
  stable across sibling cells launched on different days, so a sweep that
  spans multiple days hits the same panel snapshot for every cell.

## Spec variant convention

For each base spec `<cell>.yaml`, a sibling `<cell>_aligned.yaml` is committed
with the V1.4 split block appended. The base specs are left untouched so the
trailing-anchor counterparts remain reproducible (matching the V1.4 plan's
opt-in migration philosophy).

Canonical split block (per V1.4 D2):

```yaml
split:
  mode: date_aligned
  train_start: 2019-01-01
  train_rows: 800
  val_rows: 400
  eval_rows: 200
  test_rows: 100
  min_train_rows_per_ticker: 200
```

## Date-window pre-flight (anchor 2019-01-01)

With train_start `2019-01-01` on NYSE calendar:

- `train_end` ≈ 2022-03-15 (+ 800 trading days)
- `val_end` ≈ 2023-10-31 (+ 400)
- `eval_end` ≈ 2024-08-22 (+ 200)
- `test_end` ≈ 2025-01-14 (+ 100)
- For H=100: `test_end + 100` ≈ 2025-06-09 (≤ today 2026-06-04 ✓)
- For H=200: `test_end + 200` ≈ 2025-10-30 (≤ today 2026-06-04 ✓)

Plenty of headroom for all 19 cells. The single canonical anchor
`2019-01-01` is used for all 19 (no per-cell anchor adjustment needed).

## Sweep runtime estimate

The 38 trailing-anchor sweep cells took ~30 min – 3 h per cell, averaging
~1 h. Reruns on the same horizons skew toward the upper end because the
date-aligned slice does not shorten the train window. With 19 cells:

- Optimistic: 19 × 30 min = ~9.5 h
- Likely: 19 × 1 h = ~19 h
- Worst: 19 × 3 h = ~57 h

Expected: ~15-25 h total. The sweep will be launched as a `setsid`-detached
background process that survives the agent's session exit; the main session
will monitor via hourly wakeups.

## Sweep launch protocol

- Pinned `--snapshot-end $(date -I)` for cache-key stability across all 19
  cells (bug #226).
- `set -uo pipefail` (no `-e`) so individual cell failures do not abort the
  sweep.
- Log: `/tmp/v1_228_sweep.log`.
- Heartbeat status: `/tmp/v1_228_sweep_status.json` updated before each cell.
- One log file for the whole sweep; per-cell artifacts under
  `results/gbdt/experiments/<cell>_aligned/`.

## Post-sweep follow-up

When the sweep completes (status file shows `"status": "done"` or PID
gone), a separate sub-agent will:

2. Regenerate `results/gbdt/data/r_precision_at_k.csv` with the 19 new rows
   (cells with the `_aligned` suffix retain the suffix in the `experiment`
   column for traceability).
3. Open the PR for this branch (Phase A specs + Phase B launcher + memo +
   CSV update).
