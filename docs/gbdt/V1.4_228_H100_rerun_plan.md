## Spec variant convention

For each base spec `<cell>.yaml`, a sibling `<cell>_aligned.yaml` is committed
with the V1.4 split block appended. The base specs are left untouched so the
trailing-anchor counterparts remain reproducible (matching the V1.4 plan's
opt-in migration philosophy).

### Two distinct split blocks by horizon

**Important refinement** — discovered during pre-flight of the first launch
attempt: the user's draft used `test_rows: 100` for both H=100 and H=200
cells, but the runner enforces `per_ticker_usable = max(0, test_rows -
horizon_days)`. With `test_rows == horizon_days` (e.g. both 100), every
test row's forward label window extends into the post-test region, so
zero rows are usable and `headline_test = {}`. The H=25 P6 smoke-test
spec sidestepped this because horizon (25) < default test_rows (100), so
75 rows were usable per ticker; the H>=100 specs must be set explicitly.

**Fix**: `test_rows = horizon_days + 100` for both H values. This gives
100 usable test rows per ticker (matching the H=25 P6 effective coverage)
and consistent statistical power across the rerun.

**Cache headroom constraint**: cache currently ends 2026-05-22. The runner
also needs `cache_end >= test_end + horizon_days` so labels can be
computed. With anchor 2019-01-01:

- H=100, test_rows=200: test_end ≈ 2025-05-13, label_end ≈ 2025-10-06 (cache 2026-05-22 ✓)
- H=200, test_rows=300: test_end ≈ 2025-10-06, label_end ≈ 2026-07-24 (cache 2026-05-22 **✗**)

For H=200 the 2019-01-01 anchor overshoots the cache. **Per-H anchor
selection**:

- **H=100 (12 cells)**: anchor `2019-01-01` (canonical D2), test_rows=200
- **H=200 (7 cells)**: anchor `2018-01-01` (one year earlier), test_rows=300

Anchor 2018-01-01 for H=200:
- test_end ≈ 2024-10-03, label_end ≈ 2025-07-24 (cache 2026-05-22 ✓)
- still 100 usable test rows per ticker

## Sweep runtime estimate

The 38 trailing-anchor sweep cells took ~30 min – 3 h per cell, averaging
~1 h. Reruns on the same horizons skew toward the upper end because the
date-aligned slice does not shorten the train window. With 19 cells:

- Optimistic: 19 × 30 min = ~9.5 h
- Likely: 19 × 1 h = ~19 h
- Worst: 19 × 3 h = ~57 h

Expected: ~15-25 h total. The sweep will be launched as a `setsid`-detached
background process that survives the agent's session exit; the main session
will monitor via hourly wakeups.

## Sweep launch protocol

- Pinned `--snapshot-end $(date -I)` for cache-key stability across all 19
  cells (bug #226).
- `set -uo pipefail` (no `-e`) so individual cell failures do not abort the
  sweep.
- Log: `/tmp/v1_228_sweep.log`.
- Heartbeat status: `/tmp/v1_228_sweep_status.json` updated before each cell.
- One log file for the whole sweep; per-cell artifacts under
  `results/gbdt/experiments/<cell>_aligned/`.

## Post-sweep follow-up

gone), a separate sub-agent will:

   (cells with the `_aligned` suffix retain the suffix in the `experiment`
   column for traceability).
3. Open the PR for this branch (Phase A specs + Phase B launcher + memo +
   CSV update).
