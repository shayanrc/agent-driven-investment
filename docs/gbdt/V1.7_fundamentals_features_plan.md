# gbdt V1.7 — F18 fundamentals feature family + champion A/B

**Status: in progress (2026-07-04).** Branch `gbdt-fundamentals-features`.
Downstream of `valuation` V1 (the point-in-time PE/PS/P-FCF panel) — task #77.

## Context / hypothesis

The user's thesis: fundamentals are the next edge for the gbdt models (which use
only price/volume F1–F16). The `valuation` module now produces a daily,
point-in-time, causally-lagged panel of valuation ratios. This plan exposes them
as an **opt-in F18 feature family** and runs a **clean matched-HP A/B** to test
whether they improve the two deployed sp500 champions' test R-Precision@K.

## Design (mirrors the F17 macro precedent)

- **Opt-in only.** F18 is NOT in `_ALL_FAMILIES`; enabled via a new
  `features.candidates: all_fundamentals` token (= F1–F16 + F18). The default
  `all` token stays byte-identical → existing models/specs untouched
  (`EXPECTED_TOTAL_COLS = 279` unchanged, locked by an invariance test).
- **Per-(date,ticker) join (not date-broadcast).** Unlike macro, fundamentals
  vary per ticker. `fundamentals_features(fund_df, panel)` aligns the valuation
  panel to the gbdt panel's `(date, ticker)` MultiIndex by **symbol** (panel
  `NASDAQ:AAPL` ↔ valuation `FUND:AAPL`), then computes cross-sectional ranks
  via `groupby(level="date").rank(pct=True)` (the F14 idiom).
- **Feature set (compact, well-behaved):** the inverse **yields** (finite/signed,
  unlike raw PE) + their cross-sectional percentile ranks + TTM revenue YoY
  growth + a valuation-change (re-rating) term:
  - `fund_earnings_yield`, `fund_sales_yield`, `fund_fcf_yield` (levels)
  - `fund_{earnings,sales,fcf}_yield_xs_rank` (cross-sectional percentile at t)
  - `fund_rev_ttm_yoy` (log revenue_ttm growth vs ~252 td ago) + its xs_rank
  - `fund_earnings_yield_chg_63` (63-td change — cheapening/re-rating)
  (~11 cols; parametrized.)
- **Causality (C1).** The valuation panel value at date `t` already uses only
  filings with `filed_date ≤ t` and the close at `t` (same convention as the F2
  price features — no extra lag). Growth/change terms are strictly trailing.
  XS ranks are same-date cross-sectional (allowed, like F14). A mandatory
  leakage test perturbs a future date's fundamentals → asserts row-`t` unchanged.
- **Source.** F18 reads the pre-built `results/valuation/data/valuation_panel.parquet`
  (regenerable via `scripts.valuation.build_valuation_panel`) cache-only — a
  prerequisite data layer, analogous to macro reading the `fred_macro` cache.

## Integration surface (opt-in, `all` untouched)

- `src/gbdt/features.py`: `fundamentals_features()`; `all_fundamentals` token +
  `F18` plan branch + `fund_df` kwarg on `build_feature_matrix`; F18 NOT in
  `_ALL_FAMILIES`.
- `src/gbdt/data.py`: `load_fundamentals_panel(start, end)` (read parquet →
  `(date, symbol)`-indexed frame) + `fundamentals_panel_signature()` for the cache key.
- `src/gbdt/__main__.py`: `_fund_selected` guard, `fund_sig` into both cache
  keys, `fund_df` fetch+pass in the build branch.
- `feature_cache.py` / `universe_feature_cache.py`: optional `fund_sig` kwarg
  (mirror `macro_sig`; added to the key only when truthy).
- `tests/gbdt/test_features_fundamentals.py`: columns, cross-sectional rank,
  causality (leak), `all`-excludes-F18 / `all_fundamentals`-includes-it invariance.

## A/B (the deliverable)

For each champion cell (+50%/50d/dd25, +20%/25d/dd10): two specs, **identical
pinned XGBoost HP** (`backend.hp_starting`), `split.mode: date_aligned`,
`train_start: 2019-01-01`, `max_iterations: 1` (single fit — so ONLY
`features.candidates` differs: `all` vs `all_fundamentals`). Per the
`[[project-gbdt-macro-features-f17]]` lesson (`_260`), NOT the auto-loop.
Compare test R-Precision@{1,3,5,10,20} + eval Brier + AUC; inspect F18 feature
importances. Run via subagents (base first to warm the shared panel cache).
