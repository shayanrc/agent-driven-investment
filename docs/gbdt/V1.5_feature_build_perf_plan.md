# gbdt V1.5 — feature-build performance (vectorization)

Promoted from `V1.4_TBD.md` row 3 (GBDTPERF), surfaced by the backtests `_019`
forward-OOS cadence: the fresh-inference path rebuilds the feature matrix every
time the cache grows, and that build was single-threaded and slow (~6 min/cell).
This plan made it **3.84× faster, bit-identically**, by vectorizing the measured
hot spots — no process parallelism needed.

## Profile first (the plan that survived contact with data)

Profiled `build_feature_matrix` on the daily `--since` slice (sp500, 486 tickers
× 1859 days = 902,944 rows) with `scripts/gbdt/profile_feature_build.py`. The
result **redirected the original "parallelize the per-ticker rolling families"
plan** — those families (C-level Cython rolling) were only ~26 s total. The real
cost was Python-bound:

| Hot spot | Cost (of ~294 s) | Fix |
|---|---|---|
| **F16 `signed_days_outside_band_meta`** | **~248 s (56%)** | ~160 s manual per-ticker stitching (`.xs` + `MultiIndex.from_product` + `concat/sort`) + ~89 s Python streak loop |
| **F7 `dollar_move_rank`** rolling-apply | ~44 s | `(w[-1] >= w).mean()` per-window Python callback |
| **F13 `vol_pct`** rolling-apply | ~43 s | identical callback |
| plain rolling families (vol/skew/…) | ~26 s | already fast — **not touched** |

## What was done (all bit-identical)

1. **Vectorize the two rolling percentile-ranks** → `_rolling_pct_rank` =
   `rolling(n).rank(method="max", pct=True)`. `method="max"` gives a tied value
   the count of elements `<=` it = `(w[-1] >= w).sum()`, and `pct=True` divides
   by the window count — exactly the old `(w[-1] >= w).mean()`, but native Cython.
2. **F16 stitching refactor** — replaced the manual per-(col, sigma, ticker)
   `.xs`/`MultiIndex.from_product`/`concat`/`sort` loop with the standard
   `_per_ticker` groupby, which preserves the `(date, ticker)` index natively.
   Same streak function, same per-ticker chronological input → identical values.
3. **Vectorize the streak loop** `_signed_days_outside_band_one` with a numpy
   run-length trick (`maximum.accumulate` of change-point indices). The reset
   semantics (sign flip / band re-entry / NaN) fall out of treating each distinct
   state — with NaN as a sentinel — as a run boundary.

**Phase 3 (process parallelism) was planned but deferred as unnecessary** —
vectorization alone hit 3.84×, the residual ~77 s is spread across the
now-fast families, and process pools would add panel-pickling cost + lose the
orchestrator's `computed`-dict dependency reuse for diminishing return.

## Correctness gates (non-negotiable — this is `src/gbdt/`)

- **Isolated equality proofs** before applying each change: the rank ↔ `apply`
  reference (ties + NaN) and the streak ↔ Python-loop reference (433 cases:
  long runs, sign flips, band re-entry, NaN resets in every position, ties at
  the band edge) — both exact (atol=0).
- **Full-matrix parity gate** (`scripts/gbdt/check_feature_parity.py`):
  original vs optimized build, **all 279 columns bit-identical (max|Δ|=0,
  NaN-structure identical)** on the full 902,944-row slice (git-stash A/B).
- **Locked in CI**: two regression tests in `tests/gbdt/test_features.py` embed
  the exact reference implementations and require the current code to match them
  value-for-value, so a future refactor cannot silently change feature values.
- **746 tests pass** (gbdt + backtests). C1 causal/no-lookahead preserved
  (vectorization is per-ticker/per-window; never reorders time within a ticker).
- **Feature-cache key unchanged** — identical output → existing
  `_feature_matrix_cache.parquet` artifacts stay valid; the `_019`
  `infer_fresh_predictions` `<1e-4` self-check is unaffected.

## Result

| | full 486-ticker slice |
|---|---|
| before | 293.8 s |
| after | **76.5 s** |
| speedup | **3.84×** |

The daily `/daily-predictions` cadence (`_019`) gets this for free — each cell's
incremental re-score drops accordingly. Combined with the `_019` `--since`
trailing slice (which had already cut the full-history rebuild ~18→~6 min), the
fresh-inference path is now comfortably interactive.

## Reproducibility

Branch `gbdt-feature-build-parallel`. Changes confined to `src/gbdt/features.py`
(+ `tests/gbdt/test_features.py` regression tests + two diagnostics under
`scripts/gbdt/`). Profile: `uv run python -m scripts.gbdt.profile_feature_build`.
Parity: `uv run python -m scripts.gbdt.check_feature_parity --save … / --baseline …`.
