# _213 V1.3 Option B P9 — Empirical acceptance validation

Empirical validation of V1.3 Option B (scout + FS-prefit + combine machinery)
against acceptance criteria A1–A7 per
[`V1.3_OPTION_B_PLAN.md`](V1.3_OPTION_B_PLAN.md) § 6. Five runs on main HEAD
`9d07481` (PR #125 + all 5 Medium fixes merged). Closes the P9 acceptance gate.

## Headline

**A1–A7: 7/7 PASS.** Cell-5 R-p@1 = **0.8000** in `agent_file_protocol` mode
(STRETCH PASS — above 0.78 ceiling within 6% of the manual track 0.8286);
0.4571 in default mode (FAILS A3 alone, but agent mode is the headline gate per
plan § 6). Cells 1+3 do not regress; rare-event cell is within 0.4% of the
sweep baseline R-p@10. The scout + combine machinery delivers the value-add
predicted by [_211](_211_cell5_manual_tuning_xgb.md) on the cell it was
designed for. The lex auto-compose alone (default mode) does NOT clear A3 on
this anti-AUC cell — the agent-driven combine phase with the speed-biased
prompt is what unlocks the gate, confirming the architectural choice in plan §
3.4.1 + D12.

### A3 — Cell-5 PASSES the strong gate  **PASS (agent mode)**

| Mode | Test R-p@1 | A3 verdict |
|---|---|---|
| Agent | **0.8000** | **STRETCH PASS** (≥ 0.78) |
| Default | 0.4571 | **FAIL** (< 0.75) |

The agent-mode result is the headline. The default-mode FAIL is informative
about why agent mode exists in the plan: the lex auto-compose picked
`{max_depth=2, eta=0.01, colsample_bytree=0.3, min_child_weight=25, gamma=0.5,
subsample=0.5, scale_pos_weight=1.7291}` — eta=0.01 + heavy regularization is
the degenerate-sink path on anti-AUC cells (`metrics.json::scout::status ==
"lex_auto_compose"` and `degenerate_sink_fallback` did NOT fire — the
fallback would only trigger if scout's per-knob winner train_val_gap ~0 AND
val_brier ≈ baseline; the per-knob curves here are well-defined but the
particular lex composition lands in a slow-eta + heavy-reg corner of HP
space).

The agent-driven combine phase fixed this: among the 25 mix configs proposed,
the speed-biased SB1 (depth-2 + eta=0.1 + ES=30, cs=0.3, mcw=5,
gamma=alpha=0) won with eval R-p@1 = 0.7705 (vs lex auto-compose's 0.6270 at
combine — index 0 of 25, the runner-required zeroth comparator). After
finalization that config's calibrated test R-p@1 came out at 0.8000.

Status confirmed by `metrics.json::scout::status = "agent_combine"` (not
`"lex_auto_compose"` or `"degenerate_sink_fallback"`).

## Mechanistic reading

The cell-5 result is the clearest single piece of evidence we've ever had for
the FS+HP-driven cliff effect on anti-AUC cells:

1. **The defaults baseline** (XGBoost out-of-box: max_depth=6, eta=0.3, no ES)
   produced val_brier=0.2628 and eval R-p@1 = 0.5697 in scout's zeroth
   config. This is what every cell-5 spec without scout would have used.

2. **The scout per-knob curves** (35 configs in 168s) cleanly mapped out the
   response surface. The per-knob winners per the V1.3 D12 lex priority were:
   max_depth=2 (R-p@1=0.6434), eta=0.01 (0.6557), cs=0.3 (0.5902), mcw=25
   (0.6025), gamma=0.5 (0.6311), alpha=0.0 (default, 0.5697), subsample=0.5
   (0.6230), spw=1.7291 (0.5902). Composed lexicographically without combine
   fits, the configuration `(2, 0.01, 0.3, 25, 0.5, 0.0, 0.5, 1.7291)` produced
   eval R-p@1 = 0.6270 at combine — better than any single knob but not the
   PASS-floor 0.75.

3. **The speed-biased combine prompt** (per plan § 3.5) explicitly pushed the
   agent toward `eta ≥ 0.1 + early_stopping_rounds: 30 + colsample_bytree ∈
   {0.3, 0.4, 0.5} + scale_pos_weight=1`. Among the 5 speed-biased configs
   submitted, SB1 — `max_depth=2, eta=0.1, ES=30, cs=0.3, mcw=5, gamma=alpha=0,
   subsample=1.0, spw=1.0, n_estimators=200` — scored eval R-p@1 = 0.7705.
   The runner's ES kicked in after only ~6 trees (the cell-5 manual ceiling
   trees-count of [_211](_211_cell5_manual_tuning_xgb.md) ), giving train_brier
   = 0.2231, val_brier = 0.2241 (gap ~0.001, no overfit). The val |z| =
   −0.11 keeps the model in the native-calibration regime (the Z-gate
   from _223), preserving the prediction-tail ranking that R-p@1 measures.

4. **Finalization**: at iter_0 the calibrated eval R-p@1 = 0.7705 (anti-AUC
   flag = true; auto-disabled L1 tie-break + val_brier plateau per V1.3
   Option A); the agent stopped the loop with `should_stop=true`. Test R-p@1
   came out at 0.8000 — slightly HIGHER than eval, indicating no eval-test
   ranking inversion (a common worry on anti-AUC cells).

The structural insight: lex auto-compose composes the per-knob argmax
mechanically; that maximizes "what works on each axis in isolation" but
combines reg-toward-degenerate-sink across all axes simultaneously (eta=0.01
+ heavy mcw + heavy gamma + tight cs all pull toward an overshrunk model).
The agent-mode combine phase, with the speed-biased prompt, samples
COMPOSITIONS that disagree with lex auto-compose precisely where lex
composition is overly conservative — and finds the speed-biased configs that
cell-5 actually wants. **The default-mode A3 FAIL is the strongest evidence
yet for why agent-mode + combine machinery is the right design for anti-AUC
cells.**

### Cell-1 + cell-3 behaviour vs _225

[_225](_225_cells13_methodology_replication.md) found that "manual methodology
FAILS on cells 1+3" — defaults dominate manual tuning on strong-AUC cells.
The P9 evidence on `nasdaq100_up_10pct_25d_dd5pct` (cell-1 per this brief)
shows scout+lex auto-compose achieves R-p@1=0.5579 vs sweep 0.5368, a +3.9%
improvement. Crucially the scout's lex winner is NOT defaults — `{depth=3,
eta=0.3, cs=0.4, alpha=0.5, spw=1.6785}` (5 of 8 knobs moved off defaults).
This is consistent with _225 in the sense that the gap vs the manual XGBoost
track is structural (XGBoost-vs-CatBoost on strong-AUC cells), but it does
NOT replicate _225's "defaults dominate everything" finding on the
nasdaq100-sized cell tested here. _225 used the larger sp500 cell-1
(`sp500_up_50pct_50d_dd25pct`) which has the manual-tuning trap baked in
more deeply; the panel-size + cell-shape interaction with scout is a
candidate for V1.5_TBD investigation.

### Rare-event behaviour: lex auto-compose ≈ defaults

The rare-event cell's scout lex auto-compose moved only 3 of 8 knobs
(`learning_rate=0.2, rsm=0.4, l2_leaf_reg=1.0` — all close to CatBoost's
canonical defaults). On a cell with such an extreme imbalance (0.018 base
rate), the per-knob curves don't show big R-p@1 spreads, and lex auto-compose
naturally collapses to ~defaults — exactly the failsafe behaviour D8.A
predicts. R-p@10 = 0.1914 vs baseline 0.1921 confirms NO regression from
flipping scout on.
