# gbdt V1.3 Option A — Integrate the anti-AUC manual methodology into the agent loop (Phase 1: eval R-p@K + anti-AUC flag + degenerate-sink warning in the iter bundle)

**Goal**: make the agent-driven FS+HP loop produce the cell-5 result **automatically** — wire the three signals the manual track ([_211](_211_cell5_manual_tuning_xgb.md)) had that the current loop lacks: (1) per-iter **eval R-Precision@K**, (2) an **anti-AUC cell flag** at iter_0 looked up from the canonical sweep CSV, and (3) a **val_brier degenerate-sink warning** when val_brier approaches the trivial-constant-predictor Brier. Layer **doctrine changes** on top: SKILL.md prompts the agent to use eval R-p@K as primary signal when the flag is set; the loop disables the L1 tie-break + auto-plateau when the flag is set (both are provably wrong on these cells per [_211 § "Why the loop fails on this cell shape"](_211_cell5_manual_tuning_xgb.md)).

This is **Option A** of the two-option V1.3 plan sketched at the end of the cell-5 manual-tuning conversation. **Option B** (a "scout" response-curve phase before iter_0) is parked in `docs/gbdt/V1.3_TBD.md` (created by this PR) and gated on Option A landing + validating.

> **Status: PLAN / SPEC — not implemented.** No production code is touched by the PR that lands this doc; the diagnostic-bundle additions, the train-loop wiring, and the validation run all happen in a subsequent branch per § 6 phasing. **Held for the user's in-session review** (touches CLAUDE.md / SKILL.md / spec docs per the project's autonomous-merge carve-out).

## § 0. Decisions — RESOLVED 2026-06-02 in-session review

All 8 decisions resolved in chat. The table below records the chosen outcome + the one-line "why this won" for each.

| # | Decision | Resolved | Why this won |
|---:|---|---|---|
| D1 | Where eval R-p@K computation lives | **`build_diagnostic_bundle` extension.** | Bundle is already the per-iter signal carrier; adding eval R-p@K there is coherent. Inline in train.py couples scoring to the train loop; separate scorer adds an indirection layer for no benefit. |
| D2 | Eval predict timing | **End-of-iter (separate predict invocation after fit).** | < 1s on hist+nj=8 regardless. End-of-iter requires zero changes to fit signatures and avoids the fit-time correctness risk of accidentally driving XGBoost early-stopping off the wrong eval_set entry. |
| D3 | Anti-AUC flag source | **Canonical CSV lookup at iter_0.** Cell key built from `(universe, direction, threshold_pct, horizon_days, max_drawdown)`. Sweep-row preferred over agentloop/manual suffixed variants. | The flag captures the cell-SHAPE property, not a per-fit property. Canonical CSV is the source of truth per CLAUDE.md "Reporting conventions". If row missing → `unknown` (no auto-disable). |
| D4 | Flag thresholds | **Tighter: AUC ∈ [0.46, 0.54] AND R-Precision@10 lift > 1.8×.** Also requires updating CLAUDE.md's "What not to do — gbdt" anti-AUC rule to the same numbers — single source of truth. | Cell-5 (AUC=0.475, lift=1.94×) sits inside both with margin. Tightening preemptively reduces false-positives for the auto-disables (D6). CLAUDE.md update ships with the V1.3 implementation PR (not this plan PR). |
| D5 | Degenerate-sink warning threshold | **α = 1.05 (5% above trivial), spec-overridable via `backend.fs_hp_loop.degenerate_sink_threshold`.** Warning is INFORMATIONAL — does not auto-stop. | Catches the actual problem cases (every γ ≥ 5 on cell-5; the alpha=10 era) without false-positives on healthy near-degenerate models like lean+γ=1 (ratio 1.079 doesn't trigger). 1.02 too tight, 1.10 too loose. |
| D6 | Surface-only or auto-disable? | **Auto-disable broken machinery + surface signals always.** When flag=true: skip L1 tie-break (#187) at finalization; skip val_brier auto-plateau in `inner_stop_check`. Eval R-p@K + degenerate-sink warning surface in EVERY iter bundle regardless of flag value. | L1 + auto-plateau are *provably wrong* on anti-AUC cells per [_211 F1/F5](_211_cell5_manual_tuning_xgb.md). The agent doesn't control these mechanisms (applied at finalization / between iters), so surface-only would leave them overriding the agent's good decisions. Don't auto-switch the agent's primary signal — let the agent apply doctrine, don't force it programmatically. |
| D7 | Backward compatibility | **All 5 new fields additive + always present** with sensible defaults. Non-anti-AUC cells get them too (advisory only — auto-disables don't fire). Older checkpoints regenerate fields from current iter; no stored-state migration. | Eval R-p@K is a useful signal regardless of cell shape. Cost is the same predict pass. No-surprises design; A5 acceptance test (§ 2.2) is the regression guardrail. |
| D8 | Validation cell + acceptance | **Cell-5 spec via agent loop with V1.3 enabled.** Acceptance bands: hard fail < 0.50; soft pass 0.50–0.67 (ship + promote Option B); **PASS ≥ 0.6714 (sweep baseline floor)**; stretch ≥ 0.75 (within 10% of manual 0.829). Three sub-experiments: A4 cell-5 test outcome, A5 non-anti-AUC byte-identical regression (`sp500_up_10pct_25d_dd5pct`), A6 determinism check (second-run bit-identical predictions on A4). | Sweep baseline is the right floor (V1.3 needs to be at least as good as untuned). Stretch ≥ 0.75 is realistic (agent reasoning may differ from manual; 100% reproducibility isn't the goal). A5 is the hard gate separate from A4 — even a 0.83 cell-5 doesn't ship if A5 fails. |

**The two doctrine changes that ship with V1.3 Option A implementation** (not this plan PR):
1. CLAUDE.md "What not to do — gbdt" anti-AUC rule thresholds updated from `[0.45, 0.55] + lift > 1.5×` to `[0.46, 0.54] + lift > 1.8×` (per D4 — single source of truth with the flag).
2. SKILL.md "Sweep-top-1-aware iter_0 navigation" block extended with the eval R-p@K + degenerate-sink-warning reading prompts (per D6 — agent applies doctrine via prompt, runner enforces correctness via auto-disable).

## § 1. The capability gap

The cell-5 manual track ([_211](_211_cell5_manual_tuning_xgb.md)) beat sweep test R-p@1 by +24% in ~15 min wall-clock using 5 capabilities the agent loop doesn't have:

| Capability | Where it lives now | Why the loop lacks it |
|---|---|---|
| Eval R-p@K as per-iter signal | Manual scripts (`/tmp/cell5_mix_*.py`) | Loop emits predictions only at finalization |
| Anti-AUC cell flag at iter_0 | SKILL.md doctrine (`> Anti-AUC + strong-top-1 cells → switch to the manual-tuning track` callout, post-PR #110) | Loop's iter_0 bundle doesn't look up sweep R-p@1 + AUC from canonical CSV; agent has to do the lookup by reading the file mid-decision |
| Single-knob response curves | Manual scripts | Loop is sequential single-knob with sticky merges; no parallel fits per iter |
| Degenerate-sink warning | Manual interpretation (no signal) | Loop has no "val_brier approaching trivial baseline" detector |
| Eta+ES tiny-model regime in iter_0 | Manual scripts | Loop's default HP starting envelope skips eta+ES; defaults are eta=0.3 + no ES + n_estimators-implicit-at-hundreds |

This plan addresses **1, 2, 4** (Option A scope) — the bundle-level changes. **3** is Option B (parked in V1.3_TBD.md). **5** is doctrine-only: SKILL.md's "Sweep-top-1-aware iter_0 navigation" block already prompts the agent toward varied HP envelopes, but the agent has no per-iter eval R-p@K to validate the choice — so 5 is gated on 1.

## § 2. Goal, deliverables, acceptance test

### 2.1 Concrete deliverables (Option A scope)

1. **`DiagnosticBundle` additions** — 5 new fields (D7) populated by `build_diagnostic_bundle`:
   - `eval_r_precision_at_k: dict[int, float]` — R-Precision@K (K ∈ {1, 3, 5, 10, 20}) on the eval segment, computed against the iter's just-fit model via a held-out predict pass. Same canonical formula as `results/gbdt/data/r_precision_at_k.csv` (`(1/Q) · Σ_q r_q / min(K, R_q)` with `(p_calibrated desc, ticker asc)` stable mergesort tie-break per [project-r-precision-methodology](../../.claude/memories/project-r-precision-methodology.md)).
   - `anti_auc_flag: Literal["true", "false", "unknown"]` — set at iter_0 from the canonical CSV lookup per D3 + D4 logic; carried in every subsequent bundle (constant for the run).
   - `degenerate_sink_warning: bool` — true when `val_brier < α × weighted_base_rate_brier` (D5; α default 1.05; spec-overridable).
   - `weighted_base_rate_brier: float` — the trivial-constant-predictor's Brier on val under uniqueness weights. Computed once at iter_0 (constant for the run); included in every bundle for context.
   - `eval_segment_size: int` — number of eval rows used for scoring; Q_days_eval auxiliary count. Diagnostic visibility into how reliable the eval R-p@K signal is.

2. **`walk_forward_train` integration** — pass the carved eval segment to `build_diagnostic_bundle`; bundle builder computes the new fields. Per-iter cost: < 1s for a predict pass on eval (~18K-100K rows depending on cell).

3. **Loop-doctrine auto-disables when `anti_auc_flag == "true"`** (D6):
   - `fs_hp_loop.best_checkpoint`: skip the L1 tie-break (#187) — fall back to strict val_brier argmin among ties, OR (better) tie-break on `eval_r_precision_at_k[1]` if present.
   - `fs_hp_loop.inner_stop_check`: ignore the val_brier auto-plateau gate; rely on `should_stop` + `degradation_gate` + `max_iterations`.
   - Both behave normally for non-anti-AUC cells.

4. **SKILL.md update** — extend the existing anti-AUC callout (added in PR #110) to:
   - Document the new bundle fields the agent should read.
   - State: "when `anti_auc_flag == true`, use `eval_r_precision_at_k[1]` as the primary optimization signal and `val_brier` as secondary; do not call `should_stop` on a val_brier plateau alone — pivot to a structurally-different knob first (per playbook rule 9), then call `should_stop` only when eval R-p@K has also plateaued across ≥2 knob families."
   - Reference the new finalization tie-break behavior (eval R-p@1 → val_brier argmin fallback).

5. **CLAUDE.md update** — one bullet in "What not to do — gbdt" acknowledging the loop now exposes eval R-p@K + anti-AUC flag at iter_0, so the manual-track switchover from rule 10/11 is now mostly automatic for cells where the flag triggers. Manual track stays available for: (a) cells where the flag is `unknown` (no sweep row); (b) anti-AUC cells the agent wants to push beyond the loop's HP envelope.

### 2.2 Acceptance test (gates the V1.3 Option A *implementation* PR — a follow-up branch, not this doc)

> **Re-run cell-5 (`nasdaq100_up_10pct_50d_dd5pct.yaml`) through the agent loop with `callback_mode: agent_file_protocol` and V1.3 Option A enabled. The agent's finalized config must produce test R-p@1 ≥ 0.6714 (the sweep baseline). Stretch: ≥ 0.75 (within 10% of the manual track's 0.8286).**

Sub-criteria:
- **A1 — Bundle fields populated.** `eval_r_precision_at_k`, `anti_auc_flag="true"`, `weighted_base_rate_brier`, `degenerate_sink_warning` all present in every iter's request JSON for the cell-5 run.
- **A2 — Auto-disable triggers.** Run's `loop/checkpoint.json` shows the L1 tie-break + auto-plateau were disabled (a `disabled_reason: "anti_auc_flag"` field in checkpoint metadata).
- **A3 — Agent navigation.** Agent reads `eval_r_precision_at_k[1]` per iter and references it in the rationale on at least 50% of iterations (manual check of decision-file rationales).
- **A4 — Test outcome.** Finalized model's `metrics.json::headline_test::R_precision_at_K[1] ≥ 0.6714`. Stretch: ≥ 0.75.
- **A5 — Non-anti-AUC regression test.** Re-run one non-anti-AUC cell (e.g. `sp500_up_10pct_25d_dd5pct`) with V1.3 enabled; behavior is byte-identical to the pre-V1.3 loop (auto-disables don't trigger; bundle has the new fields but they're advisory only). Hard pass/fail.
- **A6 — Determinism.** Per-iter eval prediction pass adds no determinism risk (same model, just an extra predict on a different segment). Confirm via re-run bit-identical predictions on the validation cell.

A4 is the headline; A5 is the regression-prevention gate.

## § 3. Detailed design

### 3.1 `DiagnosticBundle` field additions

`src/gbdt/diagnostics.py::DiagnosticBundle` (dataclass) grows 5 new fields, all optional with sensible defaults to preserve backward compat:

```python
@dataclass
class DiagnosticBundle:
    # ... existing fields ...

    # V1.3 Option A additions
    eval_r_precision_at_k: dict[int, float] | None = None
    anti_auc_flag: Literal["true", "false", "unknown"] = "unknown"
    degenerate_sink_warning: bool = False
    weighted_base_rate_brier: float | None = None
    eval_segment_size: int | None = None
```

`build_diagnostic_bundle` signature grows two args (eval segment carved by `train.py`, sweep row dict from `r_precision_at_k.csv` looked up at iter_0):

```python
def build_diagnostic_bundle(
    model, X_train, y_train, w_train,
    X_val, y_val, w_val,
    *,
    # NEW
    X_eval=None, y_eval=None, mi_eval=None,
    sweep_row: dict | None = None,  # canonical CSV row for the cell, or None if absent
    degenerate_sink_threshold: float = 1.05,
    **existing_kwargs,
) -> DiagnosticBundle:
```

Backward compat: if `X_eval` is None, `eval_r_precision_at_k` stays None and the doctrine auto-disables (D6) don't trigger (`anti_auc_flag` defaults to "unknown"). Existing call sites continue to work unchanged.

### 3.2 `walk_forward_train` integration

`src/gbdt/train.py::walk_forward_train` already carves train/val/eval/test segments (`Fold.eval_idx`). Currently the eval segment is only used at finalization. V1.3 changes:

- **Iter 0**: load `results/gbdt/data/r_precision_at_k.csv`, look up the row for the cell key (built from `target.universe + direction + threshold_pct + horizon_days + max_drawdown`), pass as `sweep_row=row` to `build_diagnostic_bundle`. If no row exists (new cell), pass `None` → `anti_auc_flag = "unknown"`.
- **Every iter**: pass the eval segment via `X_eval, y_eval, mi_eval`. The bundle builder runs `model.predict_proba(X_eval)` + R-Precision@K computation. Cost: < 1s for nasdaq cells, ~3s for sp500 cells (still negligible vs the fit itself).
- **Iter 0**: compute `weighted_base_rate_brier = (p_val * (1 - p_val))` where `p_val = (y_val * w_val).sum() / w_val.sum()`. Constant for the run; cached in the loop state.

### 3.3 Anti-AUC flag logic (D3 + D4)

```python
def compute_anti_auc_flag(sweep_row: dict | None) -> Literal["true", "false", "unknown"]:
    """Apply the CLAUDE.md 'What not to do — gbdt' rule.

    AUC in [0.45, 0.55] AND R-Precision@10 lift > 1.5x -> anti-AUC strong-top-1.
    """
    if sweep_row is None:
        return "unknown"
    auc = sweep_row["AUC"]
    rp10 = sweep_row["R_precision_at_10"]
    base = sweep_row["base_rate"]
    lift10 = rp10 / base if base > 0 else 0.0
    if 0.45 <= auc <= 0.55 and lift10 > 1.5:
        return "true"
    return "false"
```

### 3.4 Degenerate-sink warning (D5)

```python
def compute_degenerate_sink_warning(
    val_brier: float, weighted_base_rate_brier: float, threshold: float
) -> bool:
    """Warn when val_brier is within threshold * trivial_baseline.

    threshold=1.05 → warn when val_brier <= 1.05 * baseline (within 5% of trivial).
    """
    return val_brier <= threshold * weighted_base_rate_brier
```

### 3.5 Loop-doctrine auto-disables (D6)

`src/gbdt/fs_hp_loop.py::best_checkpoint` reads `anti_auc_flag` from the iter-0 bundle; when `"true"`:
- Skip the L1 tie-break (gap + Z).
- If `eval_r_precision_at_k[1]` is present in all candidate iters, tie-break on it (higher wins).
- Else fall back to strict val_brier argmin.

`src/gbdt/fs_hp_loop.py::inner_stop_check` reads the flag; when `"true"`:
- Skip the val_brier auto-plateau check.
- `should_stop=True` (agent-emitted) + `degradation_gate` + `max_iterations` remain active.

Both behaviors recorded in `loop/checkpoint.json` under `auto_disabled` for audit.

### 3.6 SKILL.md + CLAUDE.md updates

SKILL.md (extend the anti-AUC callout from PR #110):

> When `iter_0_request.json::diagnostics.anti_auc_flag == "true"`, the loop has auto-disabled two known-wrong mechanisms (L1 tie-break + val_brier auto-plateau) — visible in `loop/checkpoint.json::auto_disabled`. The agent should read **`eval_r_precision_at_k[1]` as the primary optimization signal** and val_brier as secondary on these cells. Specifically: do NOT call `should_stop` on a val_brier plateau alone — pivot to a structurally-different knob family first (per playbook rule 9), and only call `should_stop` when **eval R-p@K** has also plateaued across ≥2 knob families. The `degenerate_sink_warning` (when true) means the model is approaching the trivial-constant predictor; that is the val_brier "winner" walking into the sink (per rule 10) — pivot away from the current reg direction.

CLAUDE.md (one bullet in "What not to do — gbdt"):

> Don't reach for the manual-tuning track on anti-AUC cells unless the loop's V1.3+ Option A signals (`anti_auc_flag`, `eval_r_precision_at_k`, `degenerate_sink_warning`) are insufficient. The loop now exposes these at iter_0 and auto-disables the known-wrong machinery (L1 tie-break, val_brier auto-plateau); the manual track stays available for cells where the flag is `unknown` (no sweep row) or where you want to push past the loop's HP envelope (eta+ES tiny-model regime — that's Option B territory).

## § 4. What's deliberately out of scope (parked in V1.3_TBD.md)

- **Option B — scout response-curve phase before iter_0.** Parallel single-knob fits to map the val_brier × eval R-p@K surface in one pass (playbook rule 11 stage 2). Gated on Option A landing + validating. The current iter_0 starts from defaults; Option B would start from "after-scout" winners. ~300 lines + spec keys + bundle changes.
- **Tiny-model HP envelope expansion in defaults.** Currently `hp_starting` defaults are CatBoost-shaped (depth=6, lr=0.05, ~1000 iters). Adding an XGBoost-default "tiny" alternative (depth=2, eta=0.1, ES=30, nest=500) as a spec-selectable preset belongs in V1.3 phase 2.
- **L1 tie-break general audit (#215).** The plan auto-disables L1 on anti-AUC cells. Whether L1 is correct on the other cell shapes (the question #215 asks) is a separate empirical study. If #215 concludes L1 is wrong elsewhere too, V1.4 may remove it entirely.
- **Per-iter val R-p@K.** We're adding *eval* R-p@K per iter, not val R-p@K. The cell-5 finding is that val R-p@K is too noisy (Q_days × 1 pick/day) — eval is the more reliable holdout. If a future cell shows val R-p@K is useful, additive change.
- **Sweep CSV regeneration on staleness.** The CSV is the source of truth for sweep rows; the lookup at iter_0 assumes it's current. A self-refresh path is out of scope.

## § 6. Open questions to surface during implementation (NOT for this plan PR)

- **Should the eval prediction pass be skipped when the eval segment is structurally slim?** Current `_TEST_ROWS_WARNING_THRESHOLD` warning fires on slim TEST segments; eval has no analog. If eval is < 50 days (Q_days), R-p@K may be too noisy for the doctrine auto-disables to trust. Decision deferred to phase 2.
- **What's the right `eval_r_precision_at_k[1]` plateau definition for `should_stop` guidance in SKILL.md?** "Plateau" on eval R-p@1 is harder to define than on val_brier because eval R-p@1 is integer-rich (positives per day). Heuristic: "no improvement over last 3 iters AND no movement > 0.02 absolute" — but this is for the agent to apply, not the loop's auto-machinery. Document as guidance in SKILL.md; don't codify in `inner_stop_check`.
- **How does this interact with the "fresh variant spec" workaround (cell-4 narrative in _195)?** That workaround was a response to bug #204 (auto-plateau fires on single-knob plateau). With auto-plateau disabled on anti-AUC cells, the workaround is no longer needed there. On non-anti-AUC cells the bug remains until the proper fix ships (planned separately).
