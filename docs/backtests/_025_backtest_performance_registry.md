# _025 — Canonical back-test performance registry (the back-test analog of `r_precision_at_k.csv`)

**Question:** we have a maintained, regenerable per-cell ranking registry
(`results/gbdt/data/r_precision_at_k.csv`) but no equivalent for *back-test* performance —
`backtest_summary.csv` existed but was an ad-hoc, NDX-centric survey dump (107 rows, stale at
the `_001`–`_023` arc, no regenerator, missing `_024`). Make it a real leaderboard: a
documented schema, a regenerator, and the `_024` OOS rows folded in.

**Answer:** `backtest_summary.csv` is now a **78-column registry** (was 39) regenerated by
`scripts/backtests/regenerate_backtest_performance_csv.py`, with the 10 `_024` OOS rows
added (117 total). Schema spec + column groups live in `CONVENTIONS.md § Registry CSV schema`.

## Schema design — deliberated across 7 independent sub-agents

One agent per dimension (dates, exposure/turnover, benchmark identity, data-vintage/
faithfulness, strategy-config, risk metrics, ranking-skill link), each told to push back.
What they changed from the first-pass proposal:

- **Dates** — `oos_start/oos_end` were never missing; they *are* the model's
  `test_start/test_end`. What was missing: `comparison_end` (mark-to-market end), `data_vintage`
  (cache as-of), `n_days`, `mtm_truncated`. Training dates are **joined** from
  `r_precision_at_k.csv` on `(experiment, train_start, test_end)`, not inlined (drift risk).
- **Risk** — `sharpe_strategy_gross` was 107/107 NaN (a never-filled placeholder, not
  uncomputable). Replaced by `sharpe_active_strategy` + `calmar`/`vol_annual`/`sortino`/
  `ulcer_index`/`worst_day`, all computed on the **active window** (`>= test_start`) so the
  flat pre-buffer doesn't deflate vol.
- **Exposure** — `avg_gross_exposure` alone misled in `_001` (59% cash); added
  `pct_days_invested` (reconstructed from `picks.csv`). Exit-trigger split kept as 3 columns
  (`_020`'s verdict was the trigger *mix*).
- **Config** — decomposed the free-text `strategy_class`/`sizer_class` into
  `selection_mode`/`sizing_mode`/`regime_gate`/`cost_bps`/… (never regex the class string for
  artifact rows; one-time parse for legacy). `regime_gate`/`cost_bps` are
  `run_rolling_validation` overlays → `none`/`0` for `run_backtest_cell` rows; a `runner`
  column lets both coexist.
- **Faithfulness** — `data_vintage` is the comparability key (the `_024` lesson: a back-test
  depends on the cache as-of date). `selfcheck_status`/`selfcheck_max_abs_diff`/
  `universe_delta` split out (sortable), not a free-text blob.
- **Ranking link** — realized R-p stays; **test R-p is JOINED, not duplicated** (the registry
  is regenerated independently → staleness).

## The benchmark-label fix (verified, not assumed)

The legacy `*_ndx_bh` columns were renamed to `idx_bh_*`. Before migrating, the "wrong label"
claim was **verified two ways**:

- **Code (decisive):** `run_backtest_cell.INDEX_BY_UNIVERSE` loads exactly one index per
  universe (sp500/russell→`^SPX`, nasdaq→`^NDX`, nifty→`NIFTY:…`). An sp500 run *never loads
  NDX* — so the value cannot be NDX.
- **Recompute:** sp500 row stored `+0.084` = recomputed **SPX +0.084** (NDX was +0.158);
  russell `+0.402` = **SPX +0.402** (NDX +0.501). Exact SPX matches.

Scope was **94/107 rows** (51 sp500 + 14 russell + 29 nifty), not the ~14 first guessed — and
the **values were always correct**; only the column *name* implied NDX. So the fix is a
value-preserving rename + a new `benchmark_index` (+ `benchmark_is_proxy`/`benchmark_proxy_for`
for the russell1000→SPX `^RUI`-uncached proxy). Migration verified: `max|Δ|` on every carried
legacy metric = `0.00e+00`.

## `_024` rows (10) — fully populated

Built from durable artifacts copied to `results/backtests/_024_oos_top10/<cell>/`
(`summary.json` + `equity_curve.csv` + `picks.csv`). Faithfulness parsed from the OOS batch
logs (russell PASS at ≤2.98e-08, no membership change; sp500 WARN +9/-0). `realized R-p` is
**NaN** — the `_024` windows are horizon-truncated (`mtm_truncated=True`: positions marked
open at `data_vintage 2026-06-23`, labels not yet resolved), so realized R-p is ill-defined;
the test-R-p link is the join key.

## Decisions / caveats

- **Default sort: chronological** (`run_timestamp`, `id`).
- **Legacy back-fill is best-effort** (append-only): legacy rows get the rename +
  `benchmark_index` + `excess_return_total` + `calmar` + parsed config; run-level columns
  (risk/exposure/turnover/faithfulness) are NaN (the curated CSV never stored them, and the
  177 surviving `summary.json` don't map 1:1 to the 107 curated rows).
- **Legacy index drawdown back-filled** — the curated CSV stored the index *return* but not
  its max drawdown, so `idx_bh_max_dd` was NaN for 98/117 rows. The regenerator now recomputes
  any null `idx_bh_*` via index buy-and-hold over `[test_start, test_end + horizon bdays]`
  (clipped to cache data-end) — the same window `run_backtest_cell` benchmarks on. Fills nulls
  only (authoritative values byte-unchanged, max|Δ|=0); method validated against a `_024` row
  (Δ=8e-17). Best-effort: legacy rows lack `comparison_end`, so the window is reconstructed
  from the cell's horizon (clip can differ slightly from the original run if the cache grew).
- **`universe_n` is NaN for `_024`** (the scored-universe count wasn't retained in the copied
  artifacts); `sp500_50_cbagent`'s exact self-check diff wasn't logged (status known: WARN).
- **Two deferred runner patches** would let future runs auto-populate the last gaps: persist
  the `infer_fresh_predictions` self-check dict (today stdout-only) → `selfcheck_*`/`universe_n`;
  and emit realized R-p from `run_backtest_cell` for fully-resolved (non-truncated) windows.
